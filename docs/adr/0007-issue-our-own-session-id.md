# ADR-0007. セッション ID を自前で発番して `--session-id` に渡す

- 状態: **実測・実機で確認**（2026-11-13 承認 / 同日に `--session-id` と `--resume` を実際に確認）
- 日付: 2026-11-13

## 背景

F-27 は「結果が外れていたとき、追加情報を入力して `--resume <session_id>` で再調査できる」。
素直に読むと「1 回目の実行の出力から `session_id` を読み、それを 2 回目に渡す」になる。

この経路には失敗の仕方が 2 つある。

1. 1 回目の出力 JSON が壊れている／想定と違う形だった → `session_id` が取れず、**再調査の入口が消える**
2. 解析が `--max-turns` 到達や通信エラーで途中終了した → 同じく `session_id` が取れない

**どちらも「結果が思わしくないとき」に起きる。** つまり再調査が最も必要な場面で、
再調査ができなくなる。落ちる場所（出力のパース）と困る場所（再調査ボタン）が離れている。

`claude --help` v2.1.322 の実測:

```
--session-id <uuid>   Use a specific session ID for the conversation
                      (must be a valid UUID)
```

**こちらから UUID を指定できる。**

## 決定

### 1. 撮影セッションの ID を UUID で発番し、Claude Code のセッション ID と同じ値にする

```
撮影開始 → SessionId = Guid.NewGuid()
         → 作業フォルダ %LOCALAPPDATA%\NutLens\work\<SessionId>\
         → claude -p --session-id <SessionId>
         → 再調査 claude -p --resume <SessionId>
```

作業フォルダ名・ログの相関キー・Claude のセッション ID が 1 つの値で揃う。
不具合報告でこの ID だけを聞けば、作業フォルダとログと会話を同時にたどれる。

### 2. 出力 JSON の `session_id` は「照合用」として扱う

パースできたら、自前の ID と一致するかを確かめてログに残す。
食い違っていたら**出力側の値を正**として採用する（Claude Code 側が ID を作り直した場合に備える）。
パースできなくても、自前の ID で `--resume` を試せる。

### 3. 再調査の可否は一時データの有無で決める

F-27 は「再調査は一時データが残っている間（結果画面を閉じるまで）に限る」。
作業フォルダが存在するかで判定する。結果画面を閉じると作業フォルダは消える（ADR-0005 / 5.5）ので、
そのとき再調査ボタンも無効になる。

## 実装で分かったこと（2026-11-13、Claude Code 2.1.322）

### 1. 自前の UUID がそのまま使われ、`--resume` も通った

```
# 1 回目：自前の UUID を渡す
claude -p --session-id 0f1e2d3c-4b5a-6978-8796-a5b4c3d2e1f0 "私の合言葉は「ナットレンズ」です。…"
→ 出力の "session_id" = 0f1e2d3c-4b5a-6978-8796-a5b4c3d2e1f0（渡した値そのもの）

# 2 回目：同じ ID で続きを聞く
claude -p --resume 0f1e2d3c-4b5a-6978-8796-a5b4c3d2e1f0 "さきほど伝えた合言葉を answer に入れてください。"
→ "structured_output": {"answer":"ナットレンズ"}
→ "session_id" も同じ値のまま
```

**会話は引き継がれ、セッション ID も変わらない。** F-27 の再調査はこの経路で作れる。

### 2. 会話履歴の保存先と中身（要件 5.5 の「保存先と内容は要確認」への回答）

```
%USERPROFILE%\.claude\projects\<作業ディレクトリのパスを - に置き換えたもの>\<セッションID>.jsonl
```

- **ファイル名がセッション ID そのもの。** こちらが ID を決めているので、
  利用者に「この 1 ファイル」と示せる
- 作業ディレクトリのエスケープは `:` と `\` を `-` に置き換えた形
  （例：`C:\Users\…\imgprobe` → `C--Users-…-imgprobe`）。
  **これは観察から推測した規則で、Claude Code の版で変わりうる**
- **読ませた画像は base64 の JPEG として本文に残る。** 実測:

  | もの | サイズ |
  |---|---|
  | 元の JPEG（626 × 353） | 12 KB |
  | 1 枚読ませた後の `.jsonl` | **104 KB** |
  | `"type":"image"` の出現 | 2 回 |
  | `"data"` の先頭 | `/9j/4AAQSkZJRgABAQEAYABgAAD/2wBD…`（JPEG の base64） |

  フレーム 20 枚なら数 MB 規模になる見込み。

**これは重要な帰結を持つ。** アプリが `frames/` を消しても、
**同じ画像の複製が Claude Code の会話履歴として利用者のディスクに残る。**
5.5 は「アプリからは削除しない」と定めているので削除はしないが、
**残ること・場所・消し方を利用者に明示する**必要がある（ADR-0013 で扱う）。

### 3. **同じ `--session-id` は 2 回使えない**（実装で踏んだ不具合）

解析を 2 回始めると、2 回目が起動直後に落ちた。

```
--- 終了コード: 1 / 所要 0.2 秒 ---
--- 標準エラー ---
Error: Session ID e7c9e6d2-240d-4f6b-bdaf-0031589bba0d is already in use.
```

撮影 1 回に対して解析を 2 回始める経路は実在する。

- 解析を取り消して、もう一度「解析する」を押す
- 解析が失敗して、やり直す

**この決定（セッション ID を撮影と同じにする）を素直に実装すると、
取り消した直後にもう一度押しただけで解析できなくなる。**

対応：**「既に使用中」と言われたら `--resume` で実行し直す。**

```csharp
internal static bool ShouldRetryAsResume(bool wasResume, ClaudeRunOutput output) =>
    !wasResume
    && output.ExitCode != 0
    && output.StandardError.Contains("already in use", StringComparison.OrdinalIgnoreCase);
```

退避先が `--resume` なのは都合がよい。やり直しは**前回読んだフレームを読み直さずに済む**ので、
利用枠の消費も減る。

文言での照合なので、Claude Code の版が変われば効かなくなる。
効かなくなったときは「2 回目の解析が失敗する」という形で表れる（宿題に残す）。

### 4. 通しで確認したこと（2026-11-13）

```
1 回目 : --session-id <UUID>  → ターン 5 / 12.9 秒 / $0.1183 / 拒否ツール 0 件
再調査 : --resume <同じ UUID> → ターン 2 / セッション ID も同じ
         前回のフレームの内容（赤背景の「0」、オレンジ背景の「3」）を
         画像を読み直さずに答えた＝会話が引き継がれている
```

会話履歴の大きさ（ADR-0013 の宿題への中間回答）:

| 状態 | `.jsonl` |
|---|---|
| 12 KB の JPEG 2 枚を読ませた後 | 214 KB |
| さらに再調査を 1 回 | 346 KB |

**フレーム 20 枚（1 枚 293 KB）なら、base64 化で 8 MB 前後になる見込み。**

## 影響

- `SessionId` は `NutLens.Core.Sessions.SessionId` として型を作る（`Guid` の生値を持ち回さない）。
  フォルダ名としての文字列化は `ToString("D")`（ハイフン区切り）に固定する
- Claude Code は会話履歴を `%USERPROFILE%\.claude\projects\<エスケープ済みの作業ディレクトリパス>\` に保存する。
  作業フォルダを消しても、そのフォルダは残る。**アプリからは消さない**（5.5 の指示）が、
  `claude purge <パス>` で消せることを README と初回セットアップに書く（D-07）

## 宿題

- **「already in use」の文言に依存した退避**（実装で分かったこと 3）が、
  Claude Code の版が変わっても効くか。効かなくなると「2 回目の解析が失敗する」形で表れる
- 作業フォルダを削除した後に `--resume` した場合の挙動。会話履歴は残っているが
  参照先のファイルが無い状態になる。F-27 の制約（結果画面を閉じるまで）でこの状態には入らない想定だが、確認する
- `claude purge <パス>` が、**既に消えたフォルダのパス**に対しても会話履歴を消せるか。
  消せないなら、利用者には `.jsonl` のパスを直接示す必要がある
- 作業ディレクトリのエスケープ規則（`:` と `\` → `-`）は観察からの推測。
  版が変わっても壊れないよう、パスを組み立てるのではなく
  **`projects` 配下からセッション ID 名のファイルを探す**実装にする

### 片付いた宿題

- ~~同じ `--session-id` の 2 回目の挙動~~ → `--resume` で会話が引き継がれ、ID も変わらない（実測）
- ~~会話履歴の保存先と内容~~ → `%USERPROFILE%\.claude\projects\<エスケープ済み cwd>\<セッションID>.jsonl`。
  **読ませた画像は base64 で本文に残る**（実測）

## 却下した案

| 案 | 却下の理由 |
|---|---|
| 出力 JSON の `session_id` を読んで再調査に使う | **パースに失敗した回ほど再調査したいのに、その回だけ再調査できない。** 失敗の原因（壊れた出力）と症状（ボタンが使えない）が離れていて、利用者からは理由が分からない |
| `--continue`（直近の会話を続ける）を使う | 作業ディレクトリ単位で「直近」を選ぶ仕組みなので、複数の撮影を並行したり順に行った場合にどの会話が続くかが曖昧になる。ID で名指しする方が確実 |
| 撮影セッション ID と Claude のセッション ID を別々に持ち、対応表を保存する | 対応表自体が一時データになり、5.5 の削除対象が 1 つ増える。1 つの値で足りるところに 2 つ持つ理由がない |
| フォルダ名を日時（`20261113-143012`）にする | `--session-id` が UUID を要求するため、結局 UUID も持つことになる。**2 つの識別子が併存すると、不具合報告でどちらを聞くべきか迷う** |
| `--no-session-persistence` でセッションを保存しない | 保存しないと `--resume` できない。F-27 が成立しなくなる |
