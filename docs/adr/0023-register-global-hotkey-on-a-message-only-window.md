# ADR-0023. グローバルホットキーを `RegisterHotKey` で取り、メッセージ専用ウィンドウで受ける

- 状態: **採用**（2026-11-14 承認）
- 日付: 2026-11-14

## 背景

F-04「グローバルホットキーで撮影の開始・停止ができる（**キーは設定で変えられる**）」。
6 章「タスクトレイに常駐し、すぐ撮影を始められる」。

**撮影の対象は他のアプリのウィンドウ**（ブラウザでショート動画を再生している）。
つまりホットキーは **NutLens にフォーカスが無い状態で押される。**
これがホットキーの存在理由で、ここを外すと機能そのものが要らなくなる。

決めるべきこと:

1. どの仕組みでキーを取るか
2. 受け口をどのウィンドウにするか
3. キーをどう設定に持たせるか
4. 登録できなかったとき（他のアプリが同じ組み合わせを取っている）どうするか

## 決定

### 1. `RegisterHotKey` / `UnregisterHotKey` を使う

CsWin32 に生成させる（CLAUDE.md §4.4：P/Invoke は手書きしない）。

```
RegisterHotKey
UnregisterHotKey
HOT_KEY_MODIFIERS
```

OS がキーの組み合わせを押さえ、`WM_HOTKEY` を送ってくる。
**他のアプリのキー入力を覗かない**のが、この API を選ぶ最大の理由（却下案を参照）。

### 2. 受け口は**メッセージ専用ウィンドウ**にする。メインウィンドウに登録しない

`HwndSource` を `HWND_MESSAGE`（`-3`）の子として 1 つ作り、そこに登録する。

```csharp
HwndSourceParameters parameters = new("NutLensHotkey")
{
    ParentWindow = new IntPtr(-3),   // HWND_MESSAGE
};
```

**メインウィンドウのハンドルに登録しない。**
ADR-0025 で決めるとおり、メインウィンドウは閉じるとトレイへ畳まれる。
畳むだけなら生きているが、**何かの拍子に破棄されるとハンドルが無効になり、
ホットキーが黙って効かなくなる。**

「トレイには居るのにホットキーが効かない」は、利用者が原因を特定できない壊れ方になる。
**ホットキーの寿命を、見える窓の寿命から切り離す。**

### 3. 設定は人が読める 1 行の文字列で持つ

```jsonc
{ "hotkey": { "enabled": true, "gesture": "Ctrl+Shift+F9" } }
```

`HotkeyGesture.TryParse("Ctrl+Shift+F9")` を `NutLens.Core` に置く。
Windows の API にも WPF にも触らない純ロジックなので、そのままテストできる。

**列挙型のビットを数値で書かない。** `"modifiers": 6, "key": 120` と書かれた設定ファイルは、
利用者が読めず、手で直せない。D-05 の「設定で変えられる」が実質失われる。

### 4. 登録に失敗しても起動は続け、理由を画面に出す

`RegisterHotKey` が false を返すのは、ほぼ「他のアプリが同じ組み合わせを先に取っている」。

| 起きたこと | 挙動 |
|---|---|
| 登録できた | ホットキーが効く |
| 登録できなかった | **起動は続ける。** 画面に「ホットキー（Ctrl+Shift+F9）を登録できませんでした。他のアプリが使っている可能性があります」と出す |
| 設定で無効にしてある | 登録しない。何も出さない |

**ホットキーが取れないだけでアプリを止めない。** ボタンで撮影できる。

既定は `Ctrl+Shift+F9`。

### 5. 開始と停止は同じキーにする

押すたびに切り替わる。2 つ覚えさせない。
いま撮影中かどうかは、トレイのアイコンとメインウィンドウで分かる。

### 6. 設定を変えたら、登録し直してから保存する

先に保存して登録に失敗すると、**設定ファイルには効かないキーが入ったまま残る。**

```
1. 新しいキーで登録してみる
2. 成功したら古い登録を外し、設定を保存する
3. 失敗したら古い登録のまま、理由を出して保存しない
```

**順序を間違えると、次の起動からホットキーが効かなくなる。**

## 影響

- `NativeMethods.txt` に 3 行増える
- `IHotkeyService` は `NutLens.Core`、実装は `NutLens.App`（`HwndSource` は WPF のため）
- メッセージ専用ウィンドウはタスクバーにもウィンドウ一覧にも出ないので、
  撮影対象の一覧（F-01）に現れる心配はない
- `HotkeyGesture` は `NutLens.Core` の純ロジック。テストで書式を固定する

## 実装で分かったこと（2026-11-14）

### 1. 実装は `NutLens.App` ではなく `NutLens.Capture` に置いた

影響の欄には「実装は `NutLens.App`（`HwndSource` は WPF のため）」と書いていたが、
**CsWin32 が生成する `PInvoke` は `NutLens.Capture` の内部にしか見えない。**
App 側から呼ぶには、もう 1 つ CsWin32 の設定を足すことになる。

`NutLens.Capture` は「撮影の層」ではなく**「Windows 専用の実装を置く層」**であり
（ADR-0002 / ADR-0020 決定 3 でも同じ整理をしている）、
`UseWPF` も既に有効（WIC のため）なので `HwndSource` が使える。
`Capture/Input/HotkeyService.cs` に置いた。

### 2. **既定値 `Ctrl+Shift+F9` はこの PC で空いていた**（宿題 1 つ解消）

ウィンドウを出さずに確かめる口を作った。

```powershell
dotnet run --project tools/NutLens.CaptureProbe -- --hotkey-selftest
```

実測:

```
入力     : Ctrl+Shift+F9
正規化後 : Ctrl+Shift+F9
修飾     : Control, Shift（Win32 と同じ値: 6）
仮想キー : 0x78
登録     : できた（この組み合わせは空いている）
解除     : した
```

**メッセージ専用ウィンドウ（`HWND_MESSAGE` の子）への `RegisterHotKey` が通ることも、
ここで確かめている**（決定 2）。

この自己診断は単体テストで代えられない。`RegisterHotKey` は Windows 専用 API で、
テストは `net10.0` なので `NutLens.Capture` を参照できない。
**ホットキーまわりを触ったら、必ずこれを走らせる。**

### 3. `HotkeySettings.Normalize()` で読めない文字列を既定へ戻す

設定ファイルに `"gesture": "Ctrl+??"` と書かれたままだと、
**起動のたびに「登録できません」が出続ける。**
読み込みの時点で既定へ戻すようにした（テストで固定）。

## 宿題

- `WM_HOTKEY` が実際に**押したときに**届くか（**未検証**）。
  登録が通ることは確かめたが、押していない
- 撮影中にホットキーを連打したときの挙動（二重起動の防止は `IsCapturing` で足りるか）
- 管理者権限で動いているアプリが前面にあるとき、ホットキーが届くか（UIPI の影響。未検証）
- 既定値が**他の PC で**衝突しないかは分からない（この PC で空いていただけ）

## 却下した案

| 案 | 却下の理由 |
|---|---|
| 低レベルキーボードフック（`WH_KEYBOARD_LL`） | **全アプリのキー入力を覗くことになる。** 画面と音声を扱うアプリが、キー入力まで見る必要はない。5.5 の趣旨（PC の中で一時的に使うだけ）と噛み合わない。セキュリティ対策ソフトに検出されることもある。壊れ方も悪く、**フックの処理が遅いとシステム全体のキー入力が遅くなる** |
| メインウィンドウのハンドルに登録する | トレイへ畳んだ後にウィンドウが破棄されると、**ホットキーが黙って効かなくなる。**「トレイに居るのに効かない」は原因が特定できない（決定 2） |
| WPF の `InputBindings` / `KeyBinding` | **アプリにフォーカスがあるときしか効かない。** 他のアプリのウィンドウを撮るのが目的なので役に立たない |
| 開始と停止を別のキーにする | 2 つ覚えることになる。撮影中かどうかは画面とトレイのアイコンで分かる（決定 5） |
| キーを列挙型の数値で `settings.json` に書く | 利用者が読めず、手で直せない。D-05 の「設定で変えられる」が実質失われる（決定 3） |
| キーを固定にして変更できなくする | F-04 が明示的に「キーは設定で変えられる」と要求している |
| 登録に失敗したら起動を中止する | 補助的な入力手段が 1 つ取れなかっただけ。ボタンで撮影できる（決定 4） |
| 保存してから登録する | **効かないキーが設定ファイルに残る。** 次の起動から黙って効かなくなる（決定 6） |
