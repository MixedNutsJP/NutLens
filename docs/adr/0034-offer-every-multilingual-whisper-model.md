# ADR-0034. Whisper のモデルは多言語版をすべて出し、推奨を 1 つ指す

- 状態: **採用**（2026-11-14。利用者が選択）
- 日付: 2026-11-14
- 置き換える対象: [ADR-0030](0030-download-whisper-models-with-resume-and-checksum.md) の決定 2

## 背景

ADR-0030 決定 2 は、選ばせるモデルを 4 つ（`tiny` / `base` / `small` / `medium`）に絞り、
`large` をこう却下した。

> `large` は入れない。**3 GB 近くあり、短い動画の文字起こしに見合わない。**

**この却下理由は、実測したら半分しか当たっていなかった。**

2026-11-14 に Hugging Face の `Content-Length` で測った値:

| モデル | 実測 |
|---|---|
| `tiny` | 74 MB |
| `base` | 141 MB |
| `small` | 465 MB |
| `medium` | **1462 MB** |
| **`large-v3-turbo`** | **1549 MB** |
| `large-v3` | 2951 MB |
| `large-v2` / `large-v1` | 2951 MB |

**`large-v3-turbo` は `medium` とほぼ同じ大きさ（+87 MB）である。**
`medium` を選ばせておきながら turbo を外す理由が無い。
却下理由が当てはまるのは `large-v3` 系（2951 MB）だけだった。

利用者の判断:

> モデルはすべて表示させるようにしてください（推奨を指定してください）

## 決定

### 1. 多言語版を 6 つ出す

| 表示 | 大きさ | 位置づけ |
|---|---|---|
| `tiny` | 74 MB | いちばん軽い。動作確認向け |
| `base` | 141 MB | 軽さと精度の釣り合い。**段階 3 で動作を確認した唯一のモデル** |
| **`small`** | 465 MB | **推奨**（決定 3） |
| `medium` | 1462 MB | — |
| `large-v3-turbo` | 1549 MB | `medium` とほぼ同じ大きさで、より高精度 |
| `large-v3` | 2951 MB | 最も高精度 |

### 2. 英語専用（`.en`）と旧版の `large` は出さない

| 外すもの | 理由 |
|---|---|
| `tiny.en` / `base.en` / `small.en` / `medium.en` | **日本語を文字起こしできない。** F-11 の「言語は自動判定し、日本語と英語に対応する」を満たせなくなる |
| `large-v1` / `large-v2` | `large-v3` の旧版で、同じ 2951 MB。**通常は選ぶ理由がない。** 一覧が長くなるだけ |

**「すべて」を字義どおりに取らない。** 選べることに意味がないものは出さない。
どちらも手で置いて `whisper.modelPath` で指すことはできる（D-05）。

### 3. 推奨は `small`

**ただし、これは実測に基づく推奨ではない。**

動作を確認したのは `base` だけ（段階 3 で日英の自動判別と文字起こし。ADR-0017）。
`small` 以上は**一度も動かしていない。**

`small` を推した根拠は「日本語の実用域に入る最小の大きさとされる」という
**Whisper 一般に知られている傾向**であって、このアプリで測った結果ではない。

**画面にも設計書にも、測っていないことを測ったように書かない。**
モデルごとの説明文は、**大きさと一般的な位置づけ**にとどめ、
「このアプリで N % 良くなる」のような数字を書かない。

比較の実測は宿題のまま（ADR-0017 の「tiny/small/medium の比較」）。

### 4. 説明文は「なぜ精度が効くのか」を書く

ADR-0030 の時点では、画面にこう書いていた。

> 大きいほど精度が上がり、時間とディスクを使います。

**ダウンロードの時間とディスクの消費は、進捗バーと MB 表記で目に見える。**
文章で重ねて言う価値が低い。代わりに、**この機能にとって精度が何に効くのか**を書く。

```
音声の文字起こしに使うモデルです。ナレーションから作品のあらすじを拾うのが役目なので、
聞き取りの精度が特定に影響します。
各モデルの違いは下の一覧を参照してください。あとから設定画面で入れ替えられます。
```

### 5. 一覧は選択そのものにする

6 つになったので、折りたたんだ選択肢（コンボボックス）だと**違いを読めないまま選ぶ**ことになる。
名前・大きさ・推奨の印・説明を並べた**一覧から選ぶ**形にする。

**印にはチェックボックス・ラジオボタンを使わない**（ADR-0029 実装で分かったこと 3 と同じ理由）。

### 6. モデルごとの説明文は `NutLens.App` に置く

`WhisperModelChoice`（Core）が持つのは、名前・ファイル名・大きさ・ハッシュだけ。
**表示の言葉は Core に入れない**（ADR-0026 決定 2）。

App 側が名前を鍵にして `Strings.resx` から引く。

## 影響

- `WhisperModelChoice.All` が 4 → 6 になる
- `WhisperModelChoice.Default` を `Recommended` に改名し、`small` を指す
- `WhisperSettings.DefaultModelFileName` は **`ggml-base.bin` のまま変えない。**
  あれは「`modelPath` が未設定のときに探す場所」で、既にそこへ `base` を置いている
  利用者のモデルが見えなくなる
- `WhisperModelChoiceTests` を直す（4 つ・`large` 無し・既定 `base` を確かめていた）
- 画面の選択がコンボボックスから一覧に変わる

## 宿題

- **モデルごとの精度を測っていない。** 推奨 `small` は一般的な傾向に基づく
  （ADR-0017 の宿題と同じ根。実測するには同じ音声を複数のモデルで流す必要がある）
- `large-v3` の 2951 MB を落とす時間（未測定）
- 量子化版（`q5_0` / `q8_0`）を出すかどうかは決めていない。**いまは出さない**

## 却下した案

| 案 | 却下の理由 |
|---|---|
| ADR-0030 決定 2 のまま 4 つに絞る | **却下理由が実測で崩れた。** `large-v3-turbo` は `medium` とほぼ同じ大きさ |
| `.en`（英語専用）も出す | **日本語を文字起こしできない。** F-11 を満たせなくなる（決定 2） |
| `large-v1` / `large-v2` も出す | `large-v3` の旧版で同じ大きさ。**選ぶ理由がない**のに一覧が伸びる（決定 2） |
| 量子化版も出す | 選択肢が 20 近くになる。違いを読めないまま選ぶことになる |
| 推奨を `base` にする | **唯一動作を確認したモデルではあるが**、日本語の聞き取りは弱いとされる。利用者が `small` を選んだ |
| 推奨を `large-v3-turbo` にする | 1.5 GB を既定で勧めることになる。精度を測っていない以上、大きい方を推す根拠も無い |
| モデルごとの説明に精度の数字を書く | **測っていない。** 測ったように見える書き方をしない（決定 3） |
| ダウンロード時間とディスク消費を説明文に書く | **進捗バーと MB 表記で目に見える。** 文章で重ねない（決定 4） |
| コンボボックスのまま 6 つ入れる | 折りたたまれていると、**違いを読めないまま選ぶ**ことになる（決定 5） |
| モデルの説明文を `WhisperModelChoice`（Core）に持たせる | Core が UI の言語を持つことになる。D-09 / ADR-0026 決定 2 と衝突する（決定 6） |
