# ADR-0025. 閉じるボタンではトレイへ畳み、畳むときにも一時データを消す

- 状態: **採用**（2026-11-14 承認）
- 日付: 2026-11-14

## 背景

6 章「タスクトレイに**常駐**し、すぐ撮影を始められる」と、
5.5 の削除の契機が、そのままでは噛み合わない。

> 一時データ…次のいずれかで**自動的に完全に消す**：
> ① 結果画面を閉じたとき ② 次の撮影を始めたとき ③ **アプリを終了したとき**

トレイ常駐のアプリで「×を押す」は、ふつう**終了ではなく畳む**。
すると ③ が、**利用者が「閉じた」と思った時点では起きない。**

| 利用者の操作 | 利用者の理解 | 素直に作った場合に起きること |
|---|---|---|
| 撮影する | 画像が一時的にできる | `work/<id>/frames/` に JPEG が残る |
| ×を押す | 閉じた | **トレイに畳まれただけ。画像は残り続ける** |
| （そのまま数日）| 閉じてある | **残り続ける** |

5.5 は本プロジェクトで最も壊してはいけないところ（CLAUDE.md §5）。
**「閉じたつもりなのに残っている」を作らない。**

いまの実装は `ShutdownMode` が既定（`OnLastWindowClose`）で、
メインウィンドウを閉じるとプロセスが終わり、`App.OnExit` が消している。
トレイ常駐にすると、この経路が消える。

## 決定

### 1. ×はトレイへ畳む。終了はトレイのメニューの「終了」だけ

`ShutdownMode = OnExplicitShutdown` にする。
**これを変えないと、最後のウィンドウを閉じた瞬間にプロセスが終わり、常駐できない。**

畳むときは `Hide()` し、`ShowInTaskbar = false` にする。
タスクバーに残ったまま押しても戻らない窓があると、壊れているように見える。

### 2. **畳むときにも一時データを消す**

5.5 の 3 つに、④「ウィンドウを閉じた（畳んだ）とき」を足す。

**要件を減らす方向ではなく、増やす方向に倒す。**
利用者が「閉じた」と思った時点で消えているほうが、5.5 の趣旨に合う。

### 3. 未解析の撮影データがあるときだけ確認を出す

消すものが残っているのは「撮影したが、まだ解析していない」場合だけ。
そのときだけ確認する。

```
撮影したデータがまだ解析されていません。
ウィンドウを閉じると削除されます。

［閉じて削除する］　［キャンセル］      ← 既定は「キャンセル」
```

| 状態 | 挙動 |
|---|---|
| 一時データが無い（ほとんどの回） | **黙って畳む。** 確認を出さない |
| 撮影したが解析していない | 確認を出す。既定は「キャンセル」 |
| 撮影中 | 確認を出す（撮影を止めて畳むか） |

**消すものが無いときに確認を出さない**のが要。毎回出る確認は読まれなくなり、
本当に消える回にも「はい」を押す動作だけが残る。

②「次の撮影を始めたとき」で確認を出さないのとは扱いが違う。
あちらは**利用者の意図がはっきり「次を撮る」**＝前のものは要らない。
×は「捨てる」という意思表示ではない。

### 4. トレイのメニューは 4 つだけ

| 項目 | 動き |
|---|---|
| 撮影を開始 / 停止 | ホットキーと同じ（F-04 / 6 章「すぐ撮影を始められる」） |
| ウィンドウを開く | 畳んだウィンドウを戻す |
| 設定 | 設定画面を開く |
| 終了 | `Shutdown()`。`App.OnExit` が一時データを消す |

アイコンのダブルクリックは「ウィンドウを開く」。

### 5. 終了の経路は 1 つに保つ

トレイの「終了」も、Windows のシャットダウンも、最後は `App.OnExit` を通る。
**消す処理を増やさない。** `ISessionWorkspace` に閉じたまま（CLAUDE.md §5）。

### 6. 撮影中はアイコンで分かるようにする

常駐していて、ウィンドウが畳まれていて、ホットキーで撮影が始まる。
**画面を見ずに撮影が始まる状況が作れる**ので、動いていることが分かる必要がある。

待機中と撮影中でアイコンを変える。

## 影響

- `H.NotifyIcon.Wpf` 2.4.1（MIT）が依存に加わる。**ライセンスは ADR-0009 で確認済み**
- `ShutdownMode` の変更は影響が広い。**どこかで `Shutdown()` を呼び忘れると、
  プロセスが残り続ける**（タスクマネージャにしか現れない）
- `ITrayIconService`（Core 抽象 / App 実装。ADR-0009 決定 2）
- メインウィンドウの `OnClosing` で畳む処理を引き受ける

## 実装で分かったこと（2026-11-14）

### 1. H.NotifyIcon.Wpf 2.4.1 は .NET 10 で起動した（ADR-0009 の宿題を一部解消）

アプリを起動して 6 秒後の状態を確かめた。

```
MainWindowTitle : 'NutLens — ショート動画の作品特定'
見えているウィンドウ : 1 つ（メインウィンドウのみ）
標準エラー           : 空
```

トレイの作成（`TaskbarIcon` の生成と `ForceCreate()`）は `OnStartup` の中で行うので、
**ここで例外が出ていればエラーダイアログが 2 つめの可視ウィンドウとして現れる。**
現れていない＝例外が出ていない。

**ただしアイコンがトレイにどう見えるかは目視していない。**
「動いた」と「正しく見えた」を同じに書かない。

### 2. アイコンは 32×32 の単色図形を生成して同梱した

`Resources/tray-idle.ico`（灰色のレンズ）と `tray-capturing.ico`（赤いレンズ）。
`Resource` としてアセンブリに埋め込み、`pack://application:,,,/Resources/…` で読む。

**見栄えは最低限。** 段階 5（配布）でアプリのアイコンを作るときに揃える。

### 3. 畳まれている窓は所有者にできない

トレイの「設定」からダイアログを開くとき、
畳んだ（`Hide()` した）メインウィンドウを `Owner` にすると WPF が例外を投げる。
`IsVisible` を見て、畳まれていれば `Owner = null` にしている。

## 宿題

- **トレイのアイコン・メニュー・×での畳みの目視が未了**（起動が通ったことしか確かめていない）
- アイコンの見栄え（段階 5 でアプリのアイコンと揃える）
- Windows のシャットダウン・サインアウトで `OnExit` が確実に呼ばれるか（**未検証**）。
  呼ばれないなら `SessionEnding` も拾う
- 畳んだ状態で長時間放置したときのメモリ（起動直後は約 155 MB。長時間は未測定）

## 却下した案

| 案 | 却下の理由 |
|---|---|
| ×で終了する（トレイに常駐しない） | 6 章が常駐を明示的に要求している |
| ×で畳むが、一時データは終了時だけ消す | **利用者が「閉じた」と思った時点で消えない。** 5.5 の 3 つの契機のうち 1 つが、押したつもりでも起きない。画像が数日残ることになる（決定 2） |
| 畳むときに常に確認を出す | 消すものが無いときにも出る。ほとんどの回で無駄になり、読まれなくなる。**本当に消える回にも「はい」を押す動作だけが残る**（決定 3） |
| 畳むときに黙って消す | 「設定を直そうと閉じたら、撮った画像が消えた」が起きる。②次の撮影 と違い、**×は「捨てる」という意思表示ではない**（決定 3） |
| 最小化でもトレイへ畳む | 最小化は「後で戻る」という意思表示で、閉じるとは違う。畳むとタスクバーから消え、**戻し方が分からなくなる** |
| `ShutdownMode` を既定のままにする | 最後のウィンドウを閉じた瞬間にプロセスが終わる。**常駐できない**（決定 1） |
| トレイのメニューに全設定を並べる | 設定画面がある。トレイのメニューが長いと、目的の項目を探すことになる |
| 撮影中かどうかをバルーン通知で知らせる | 撮影のたびに通知が出る。**2 秒ごとに撮る機能で、通知が邪魔になる。** アイコンで足りる（決定 6） |
