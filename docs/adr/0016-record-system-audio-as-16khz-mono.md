# ADR-0016. システム音声を WASAPI ループバックで録り、16 kHz モノラルの WAV で書く

- 状態: **採用**（2026-11-14）
- 日付: 2026-11-14

## 背景

F-11 は「WASAPI ループバックでシステム音声を記録し（NAudio を想定）、ローカルで文字起こしする」。
**API とライブラリは要件で指定されている**ので、決めるのは録り方のほうになる。

決めるべきこと:

1. どの形式で `audio.wav` に書くか
2. 撮影との関係（同時に始めて同時に止める）
3. 音声デバイスが無い・無音のときどうするか
4. ループバックは**システム全体の音**を録ることへの扱い

4 が効いてくる。ループバックは「この動画の音」ではなく
**スピーカーに出ている音すべて**を拾う。通知音、別のアプリの音、他のタブの音が混ざる。

## 決定

### 1. 16 kHz・モノラル・16 bit PCM で書く

whisper が内部で使う形式がこれ。**録りながら落とす。**

| 項目 | 値 |
|---|---|
| 標本化周波数 | 16 000 Hz |
| チャンネル | 1（モノラル） |
| 量子化 | 16 bit 整数 |
| 60 秒ぶんの大きさ | 約 1.9 MB |

ループバックが返すのは既定で 48 kHz・2 ch・32 bit float などデバイス依存の形式なので、
NAudio の `MediaFoundationResampler` で変換してから書く。

**撮影後にまとめて変換しない。** 元の形式のまま 60 秒録ると 20 MB を超え、
一時データ（5.5）として扱う量が無駄に増える。

### 2. 撮影と同時に始め、同時に止める

`CaptureSessionService` が録音の開始と停止も持つ。
要件 4 章の「画面のフレームと、システム音声を同時に記録する」をそのまま写す。

録音は `ISessionWorkspace` が作ったセッションフォルダの `audio.wav` へ直接書く。
**音声は ADR-0005（メモリに持ってから書く）の対象外。**
60 秒で 1.9 MB あり、メモリに溜める利点がない（ADR-0005 の「影響」に明記済み）。

### 3. 録れなくても撮影は止めない

| 状況 | 挙動 |
|---|---|
| 音声デバイスが無い | 画面の撮影だけ続ける。`audio.wav` は作らない |
| 録音の開始に失敗した | 同上。理由を結果に添えて利用者に出す |
| 全部無音だった | `audio.wav` は作るが、文字起こしは「音声なし」として扱う |

**補助情報が取れなかっただけで解析を止めない**（概要設計 §10.1 の方針）。

### 4. 「システム全体の音を録る」ことを画面に出す

撮影の設定の近くに常時表示する。

```
注意：システム全体の音を録ります。通知音や他のアプリの音も入ります。
```

**警告ではなく事実の提示として出す。** 止める必要はないが、知らないと
「なぜ関係ない音が文字起こしに出るのか」が分からない。

### 5. 録音の有無を設定で切れるようにする

`CaptureSettings.RecordAudio`（既定 **true**）。
音を出せない状況（会議中など）で撮りたい場合に、録音だけ止められるようにする。

## 影響

- `NAudio` 3.3.0（MIT）が依存に加わる
- `MediaFoundationResampler` は Media Foundation に依存する。
  Windows N エディションでは追加の機能パックが要る場合がある（宿題）
- `audio.wav` は一時データ。他と一緒に消える（5.5）

## 実装で分かったこと（2026-11-14）

### 1. NAudio 3.3.0 で API が変わっていた

`WasapiLoopbackCapture` は非推奨になり、ビルドが**エラーで止まった**
（`TreatWarningsAsErrors` のため）。

```
Use WasapiRecorderBuilder.WithProcessLoopback() for process-specific loopback,
or configure a WasapiRecorder with a render device for system-wide loopback.
```

```csharp
// 既定の再生デバイスのループバック
WasapiRecorder capture = new WasapiRecorderBuilder().WithLoopbackCapture().Build();
```

`DataAvailable` も `EventHandler` ではなく、`ReadOnlySpan<byte>` を渡す零コピーの委譲に変わった。
メソッド参照では受けられないので、ラムダで受けている。

**`WithProcessLoopback(プロセスID, …)` が使えるようになっている。**
却下案で「実装が重い」として退けたが、今は 1 行で済む。
撮影対象がウィンドウなら、そのプロセス ID も取れる。
**要件は「システム音声」なので今回は使わないが、選べる状態にはなった**（宿題）。

### 2. **書き出しが暴走して 1.2 GB の WAV を作った**（直した）

利用者が録音の自己診断を走らせたところ、出力が途中で止まったまま返ってこなくなった。
調べると、**7 秒の音声を録っているはずの WAV が 1.18 GB まで育っていた。**
プロセスは 2 分間回り続けており、毎秒 10 MB ほど書いていた計算になる。

原因は `BufferedWaveProvider.ReadFully` の既定値。

```csharp
// 「変換器から取れるだけ取って書く」ループ
while ((read = this.resampler.Read(converted)) > 0)
{
    this.writer.Write(converted[..read]);
}
```

**`ReadFully` の既定は true。** たまった音が尽きても、
`BufferedWaveProvider.Read` は**無音を詰めて要求されたぶんを返す。**
つまり `Read` が 0 を返さず、ループが永久に回り、無音を書き続ける。

```csharp
this.buffer = new BufferedWaveProvider(format, TimeSpan.FromSeconds(5))
{
    DiscardOnBufferOverflow = true,
    ReadFully = false,          // ← これが無いと止まらない
};
```

**既定値が直感と逆だったために起きた。**
「尽きたら 0 が返る」と思い込んでいたが、既定は「尽きても埋めて返す」だった。

歯止めも入れた。書き出しが 128 MB（撮影時間の上限 3600 秒ぶん ＋ 余裕）を超えたら打ち切る。
**この歯止めが無いと、不具合が「ディスクが埋まる」形で表れる。**

### 3. 無音でも再現し、無音で確かめられる

この暴走は**音が鳴っていなくても起きる**（ループバックは無音のバッファも届けるため）。
裏を返せば、**音を出さずに確かめられる。**

```powershell
# 3 秒ぶん録って、量が妥当かを見る（スピーカーから音は出ない）
dotnet run --project tools/NutLens.CaptureProbe -- 3 --audio-idle
```

修正後の実測:

```
書けた : 94 KB
目安   : 93 KB（3.0 秒ぶん）
判定   : 妥当（暴走していない）
形式   : 16000 Hz / 1 ch / 16 bit（3.0 秒）
```

**録音まわりを触ったら、必ずこれを走らせる。**
テスト計画（詳細設計 04 §9）に単体テストとしては書けない
（NAudio は `NutLens.Capture`（`net10.0-windows`）にあり、
テストは `net10.0` なので参照できない）。

### 4. 形式は設計どおりだった

16 kHz・モノラル・16 bit で書けていることを、録れた WAV のヘッダで確認した（決定 1）。

**実際に音が入るか・文字起こしが通るかは未確認。** 音を再生した自己診断が要る。

## 宿題

- **音が出ている状態での録音と文字起こしの通し確認（未了）。**
  形式と量が妥当なことは確かめたが、**実際に音が入っているかは見ていない**
- `WithProcessLoopback` に切り替えると、通知音や他のアプリの音を除ける。
  実装で分かったこと 1 のとおり簡単になったので、段階 4 以降で見直す価値がある
- **Windows N エディションで `MediaFoundationResampler` が動くか（未検証）。**
  動かないなら、自前の線形補間に落とす
- 48 kHz → 16 kHz の変換で、文字起こしの精度がどれだけ変わるか（測っていない）
- 複数の再生デバイスがあるとき、既定デバイス以外の音を録りたい場合の扱い（段階 4 以降）

## 却下した案

| 案 | 却下の理由 |
|---|---|
| デバイスの形式のまま録り、文字起こしの直前に変換する | 60 秒で 20 MB を超える。**一時データとして扱う量が 10 倍になる**（5.5 は量を絞ることを求めている） |
| マイク入力から録る | スピーカーから出た音を空気越しに拾うことになり、品質が落ちる。イヤホンだと何も録れない |
| プロセス単位のループバック（`ActivateAudioInterfaceAsync` の process loopback） | 「この動画の音だけ」を録れる点は優れているが、Windows 10 2004 以降かつ実装が重い。**要件は「システム音声」としか言っていない**ので、過剰 |
| 音声を録らない（文字起こしを諦める） | F-11 が要求している。あらすじのキーワードはナレーションに多く含まれる |
| 無音を検出して自動で録音を止める | 無音判定のしきい値を決める根拠がない。**測っていない値で挙動を変えない** |
| 録音を既定でオフにする | F-11 は録ることを前提にしている。オフが既定だと、利用者が気づかないまま精度が落ちる |
