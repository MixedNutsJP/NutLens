# ADR-0018. OCR は間引いた後のフレームに対して行い、言語が無ければ解析を続ける

- 状態: **実測・実機で確認**（2026-11-14。実物のフリップ動画 65 枚で確認）
- 日付: 2026-11-14

## 背景

F-12 は「残したフレームに `Windows.Media.Ocr` で OCR をかけ、テロップ・字幕を `ocr.txt` に
まとめる（フレームごとの撮影時刻つき）。同じ文字列は重複を除く」。

API は要件で指定されている。決めるべきことが 3 つある。

### 1. どの画素に対して OCR をかけるか

ADR-0005 で、撮影中はメモリに**符号化後の JPEG だけ**を持つことにした。
原寸の BGRA は符号化した直後に捨てている。

| 案 | OCR をかける対象 | 回数 |
|---|---|---|
| (a) 撮影中、符号化の前 | 原寸の BGRA | 採用したフレーム全部（最大 200） |
| (b) 間引いた後、JPEG を復号して | 縮小後の JPEG | **残った分だけ（既定 20）** |

### 2. 日本語の OCR が入っていない環境をどうするか

`Windows.Media.Ocr` は**言語パックが入っている言語しか読めない。**
日本語の OCR は、日本語の言語機能が入っていないと使えない。
英語は多くの環境に入っているが、保証はない。

### 3. 重複をどう除くか

ショート動画はループ再生され、テロップは数秒間出しっぱなしになる。
同じ文字列が何度も出る。

## 決定

### 1. 間引いた後のフレームに対して行う（案 b）

理由は 2 つ。

- **回数が 10 分の 1 になる。** 200 回が 20 回になる
- **Claude が読む画像と、OCR が読んだ画像が同じものになる。**
  原寸でしか読めない小さな文字を `ocr.txt` に載せても、
  Claude が見るフレームにはそれが写っていない。食い違いの元になる

JPEG を `BitmapDecoder` で復号し、`SoftwareBitmap`（BGRA8）にして `OcrEngine` に渡す。

**ADR-0008 の宿題「JPEG 品質 85 でテロップの OCR 精度が落ちないか」は、
この決定によって実際に効いてくる。** 読めない場合は品質を上げる（宿題）。

### 2. 言語は「日本語 → 英語 → 利用できるもの」の順に選び、無ければ飛ばす

```
1. 利用できる認識言語に ja があれば ja
2. 無ければ en
3. 無ければ、利用できる最初の言語
4. 1 つも無ければ OCR を飛ばし、その旨を利用者に出す
```

**OCR が使えなくても解析は続ける**（概要設計 §10.1）。
`ocr.txt` は作らず、プロンプトには「OCR の結果はありません」と入る（ADR-0014）。

選んだ言語は `ocr.txt` の先頭に書く。
日本語のテロップを英語の認識器で読むと、意味のない文字列が並ぶ。
**何の言語で読んだかが分からないと、結果を見た人が判断できない。**

### 3. 重複は「正規化した文字列」で除く

| 処理 | 理由 |
|---|---|
| 前後の空白を落とす | 認識の揺れ |
| 連続する空白を 1 つにまとめる | 同上 |
| **全角と半角を揃える**（`FormC` 正規化） | 「１」と「1」が別物にならないように |
| 大文字小文字は揃えない | 原文のまま残す。固有名詞の手がかりになる |

正規化は**重複判定にだけ使い、出力は原文のまま**にする。

同じ文字列が複数のフレームに出たら、**最初に出たフレームの時刻だけを載せる。**

### 4. 出力の形

```
# テロップ・字幕の OCR（言語: ja / フレーム 12 枚中 9 枚から検出）

[  0.0s] タクシーに乗ったら
[  0.0s] 新幹線より速かった
[  2.0s] 1台のタクシーを見つけました
[ 12.0s] ©TAXi3 (2003)
```

時刻はフレームの経過秒（撮影開始から）。

## 実装で分かったこと（2026-11-14）

実物のフリップ動画のフレーム 65 枚（ブラウザの窓ごと撮影、1280 × 720 の JPEG 品質 85）で測った。
**撮影は伴わない。既にあるフレームで測れる。**

```
利用できる認識言語: ja (日本語)
検出したフレーム  : 65 / 65 枚
重複除去後の行    : 133 行
所要              : 4.7 秒（1 枚あたり 73 ms）
```

### 1. JPEG 品質 85 でも日本語の字幕はよく読める（ADR-0008 の宿題の回答）

```
[   0.0s] タクシーに乗ったら
[   4.0s] 絶体絶命瞬間
[   6.0s] 1 台のタクシーを見つけました
[  10.1s] 20 分で空港まで
[  16.1s] メーター 4 倍の先払いを
```

**品質を上げる必要は無い。** 案 a（原寸で読む）へ戻す理由も無い。

### 2. 日本語の認識は 1 文字ずつ「語」として返る（直した）

最初の実装では、こう出ていた。

```
[   0.0s] タ ク シ ー に 乗 っ た ら
[   4.0s] 絶 体 絶 命 瞬 間
```

Windows の日本語 OCR は 1 文字ずつを語として扱うため、行の文字列が分かち書きになる。
**これは認識器の都合であって、画面に出ていた文字列ではない。**

決定 3 の「出力は原文のまま」を次のように改める。

> **認識器が入れた空白だけを詰める。** 両隣が日本語の文字である空白を落とす。
> **英数字の間の空白は残す**（「TAXi 3」を「TAXi3」にすると画面に無い文字列を作ってしまう）。
> 全角半角の変換は、これまでどおり重複判定にだけ使い、出力には持ち込まない。

### 3. この PC には `ja` しか入っていない

```
利用できる認識言語: 1 件
  - ja (日本語)
```

決定 2 の「ja → en → 最初の 1 つ」のうち、**en には届かない。**
英語のテロップ（原題やロゴ）は日本語の認識器が読むことになり、実際に崩れた。

```
©TAXi3 (2003)  →  「@TAXロ ( 200a」「TAX ロ ( 200 引」「④ TAX ロ ( 200a」など
```

**同じ表示が毎回違う誤りになるので、重複除去をすり抜けて行数を押し上げる。**
133 行のうち相当数がこれとブラウザの UI 文字。

対処は 2 つあるが、どちらも今は入れない。

| できること | なぜ今はやらないか |
|---|---|
| 英語の言語機能を入れてもらう | 利用者の環境を変えさせることになる。README に書く（段階 5） |
| 動画の部分だけを矩形で選ぶ | **既に画面でヒントを出している**（ADR-0015 決定 3）。ブラウザの UI 文字が消えるぶん、効果は大きい |

### 4. 速さは問題にならない

1 枚 73 ms。既定の上限 20 枚なら 1.5 秒ほど。

## 影響

- 追加の NuGet 依存は無い（`Windows.Media.Ocr` は OS の機能）
- JPEG の復号が 20 回走る。1 枚あたり数ミリ秒の規模
- 日本語の言語機能が入っていない環境では、日本語のテロップが読めない。
  **この制約は回避できない**ので、README に書く（段階 5）

## 宿題

- **英語の認識言語が入っている環境での挙動（未検証）。**
  この PC には ja しか無く、ja → en の退避が一度も通っていない
- 動画の部分だけを矩形で選んだときに、ブラウザの UI 文字がどれだけ減るか（未測定）
- 英語の認識言語を入れてもらう案内を README に書く（段階 5）

### 片付いた宿題

- ~~この環境で利用できる認識言語~~ → **`ja` のみ**（実装で分かったこと 3）
- ~~JPEG 品質 85 でテロップが読めるか~~ → **読める。** 品質を上げる必要は無い（同 1）
- ~~重複除去が効いているか~~ → 効いている。ただし**誤認識が毎回違う文字列になる**ぶんは
  すり抜ける（同 3）

## 却下した案

| 案 | 却下の理由 |
|---|---|
| 撮影中、符号化の前に原寸でかける（案 a） | **OCR の回数が 10 倍になる**（最大 200 回）。さらに、間引きで捨てたフレームの文字まで `ocr.txt` に載り、**Claude が見ていない画像の文字が手がかりとして出る** |
| 原寸の BGRA をメモリに残して後でかける | ADR-0005 に正面から反する。4K で 1 枚 33 MB |
| OCR の言語を設定で固定させる | 入っていない言語を選べてしまう。**選べるのは「入っているもの」だけ**にするほうが、設定の意味が明確 |
| 日本語が無ければ OCR 全体を飛ばす | 英語のテロップ（原題やロゴ）は読める。読めるものまで捨てる理由がない |
| 重複除去で大文字小文字も揃える | `TAXi3` と `taxi3` が同じ扱いになる。**固有名詞の表記は手がかり**なので、原文を保つ |
| 重複した文字列の時刻を全部載せる | 固定テロップは全フレームに出る。20 枚ぶんの時刻が並んで読めなくなる |
| OCR の結果を信用して候補に直結させる | 認識は誤る。`analyzer/CLAUDE.md` の「事実と推測を分ける」に従い、手がかりの一つとして渡すだけにする |
