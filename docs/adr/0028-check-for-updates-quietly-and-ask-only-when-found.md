# ADR-0028. 更新は起動時に黙って確認し、見つかったときだけ尋ねる

- 状態: **採用**（2026-11-14 承認）
- 日付: 2026-11-14

## 背景

D-02「自動更新に対応する。更新元は GitHub Releases とし、**起動時に更新を確認して、
利用者の同意を得てから適用する**」

「確認する」と「同意を得てから適用する」は要件で決まっている。決めるのは**出し方**。

1. 確認に失敗したとき（オフライン・GitHub に繋がらない）どうするか
2. 見つからなかったときに何か出すか
3. 同意しなかったとき、次はいつ聞くか
4. 撮影中・解析中に出てよいか

4 が効いてくる。このアプリはトレイに常駐し、**ホットキーで画面を見ずに撮影が始まる**
（ADR-0025 決定 6）。撮影の最中に更新のダイアログが前面に出ると、
**その瞬間の画面がフレームに写り込む。**

## 決定

### 1. 起動時に 1 回だけ、背景で確認する

UI を止めない。確認が終わるまで待たせない。

```
起動 → ウィンドウを出す → （背景で）更新を確認 → 見つかれば尋ねる
```

### 2. 確認に失敗したら**黙る**

オフライン、GitHub に繋がらない、レート制限。いずれも**何も出さない。**

更新の確認は利用者が頼んだ操作ではない。
**頼んでいないことの失敗を知らせない。**
ネットワークに繋がっていない利用者に、起動のたびにエラーが出ることになる。

ただし**握りつぶして忘れない。** 設定画面の「このアプリについて」に
「最後に確認した日時」と結果を出す。自分で確かめたい人はそこで分かる。

### 3. 見つからなかったら何も出さない

「最新です」を起動のたびに出さない。

### 4. 同意しなかったら、**その版はもう聞かない**

```
0.2.0 が見つかった → 「いいえ」 → 0.2.0 については二度と聞かない
0.3.0 が出た       → また聞く
```

断った版を起動のたびに聞き直すと、**「いいえ」を押す動作だけが習慣になる。**
そうなると、本当に入れてほしい更新も同じ動作で流される。

断った版は `settings.json` に 1 つだけ覚える（`update.skippedVersion`）。

### 5. 撮影中・解析中は出さない。終わってから出す

**撮影中にダイアログを前面に出すと、その瞬間がフレームに写り込む。**
解析中に出すと、利用者の利用枠を使っている処理の邪魔になる。

見つかった更新は保持しておき、**待機中になった最初の機会**に出す。

### 6. 適用は「今すぐ再起動」か「次の起動時」を選べる

```
NutLens 0.2.0 が公開されています（現在 0.1.0）。

［今すぐ更新して再起動］　［次回の起動時に適用］　［この版は見送る］
```

ダウンロードは同意の後に行う。**同意の前に落とさない。**
使うか分からないものを、利用者の回線で先に落とさない。

### 7. 更新の確認そのものを切れるようにする

`update.checkOnStartup`（既定 **true**）。

**これは D-08 の「テレメトリを入れない」とは別の話。**
更新の確認は GitHub へ出ていく通信なので、止めたい利用者が止められるようにする。
止めた場合は、設定画面から手で確認できる。

## 影響

- `UpdateSettings` が増える：`CheckOnStartup`（true）/ `SkippedVersion`（null）/ `LastCheckedAt`（null）
- `IUpdateService`（Core 抽象）/ `VelopackUpdateService`（App 実装）
- `NutLensSettings.CurrentVersion` は上げない（既存の項目の意味は変わらない）
- 更新の通信先は GitHub Releases のみ。**端点は定数**（ADR-0019 決定 6 と同じ理由で、設定では変えない）

## 宿題

- **一度も更新していない。** 版を 2 つ作って差分を当てる確認が要る
- 「次回の起動時に適用」が Velopack でどう実現されるか（`WaitExitThenApplyUpdates` の挙動。未検証）
- GitHub のレート制限に当たる頻度（起動のたびに 1 回なので問題にならないはずだが、未測定）
- 断った版の覚え方が、ダウングレード（公開を取り消した場合）で悪さをしないか

## 却下した案

| 案 | 却下の理由 |
|---|---|
| 確認の失敗を画面に出す | 利用者が頼んだ操作ではない。**オフラインの利用者に、起動のたびにエラーが出る**（決定 2） |
| 失敗を完全に握りつぶす | 「更新が来ない」理由を調べる手段が無くなる。最後の確認結果は残す（決定 2） |
| 「最新です」を毎回出す | 起動のたびに閉じる操作が増える。**何も変わっていないことを知らせる価値が低い**（決定 3） |
| 断っても起動のたびに聞き直す | **「いいえ」を押す動作だけが習慣になる。** 本当に必要な更新も同じ動作で流される（決定 4） |
| 断ったら二度と聞かない（版に関係なく） | 次の版も届かなくなる。**不具合の修正が永久に届かない**（決定 4） |
| 同意を待たずに先にダウンロードしておく | 使うか分からないものを利用者の回線で落とす。従量課金の回線では実害になる（決定 6） |
| 同意なしに自動で適用する | **D-02 が明示的に「同意を得てから」と言っている** |
| 撮影中でも出す | **その瞬間の画面がフレームに写り込む。** 解析に関係ない自分のダイアログが手がかりに混ざる（決定 5） |
| 更新の確認を切れなくする | 外へ出る通信を止める手段が無くなる。このアプリは通信を絞ることを主題にしている（決定 7） |
