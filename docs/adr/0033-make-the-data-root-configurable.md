# ADR-0033. データの保存先を設定で変えられるようにし、場所の指定だけを別に持つ

- 状態: **採用**（2026-11-14。利用者が選択）
- 日付: 2026-11-14

## 背景

利用者から次の要望があった。

> できれば C ドライブにデータを保管したくなく、インストール先ディレクトリ内に
> 一時ファイルやログ、設定などを生成する形にできますか？

いまの実装は保存先を固定で書いている。

```csharp
private static string DefaultRoot() => Path.Combine(
    Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData),
    ApplicationDirectoryName);
```

**これは D-05 を満たしていなかった。**

> D-05　環境に依存する値（`claude` のパス、モデルのパス、**保存先**）を固定で書かない。
> **すべて設定で変えられるようにし**、初期値は自動で探す

5.5 と 6 章が `%LOCALAPPDATA%\NutLens\…` と書いているのは**初期値**であり、
D-05 はそれを**変えられること**を求めている。要望は要件側に沿っている。

決めるべきことは 3 つ。

1. 保存先をどこに持つか
2. **指定した場所そのものを、どこに覚えるか**
3. 変えたときに、いまあるデータをどうするか

**2 が効いてくる。** 保存先の指定を `settings.json` に書くことはできない。
`settings.json` 自身が保存先の中にあるからで、**どこを読めばよいかが決まらない。**

## 決定

### 1. 保存先は 2 段で決める

```
1. 「場所の指定」ファイルがあれば、そこ
2. 無ければ %LOCALAPPDATA%\NutLens   ← 初期値（5.5 / 6 章）
```

**3 段にしない。** 「設定 → インストール先 → LOCALAPPDATA」のように増やすと、
**いまどこを見ているかが利用者にも開発者にも分からなくなる。**

いまの保存先は**設定画面に常時表示する。** 迷ったら画面を見れば分かる状態にする。

### 2. 「場所の指定」は 1 行のテキストファイルで、**`current\` の外**に置く

```
<インストール先>\
  current\          ← アプリ本体。**更新のたびに丸ごと置き換わる**
  packages\
  data-dir.txt      ← ★ ここ。更新で消えない
  Update.exe
```

**`current\` の中（exe の隣）に置いてはいけない。**
Velopack は更新のたびに `current\` を作り直すので、
**更新したら保存先の指定が消え、初期値に戻る。**
そのとき利用者には「更新したら設定と履歴が消えた」ように見える。

置き場は Velopack の `RootAppDir`。インストールされていない場合
（ポータブル版・開発中の `dotnet run`）は exe のあるフォルダ。

**`settings.json` には書かない。** それ自身が保存先の中にあるため、
どこを読めばよいかが決まらない（鶏と卵）。

### 3. 移してから指定を書き、最後に元を消す

**順序を間違えると、戻せない形で壊れる。**

```
1. 新しい場所に書けるか試す（書けなければ何も変えない）
2. いまのデータを新しい場所へ**コピー**する
3. コピーを照合する（ファイル数と合計の大きさ）
4. ★ data-dir.txt を書く
5. 元の場所を消す
```

| 途中で落ちた場所 | 起きること |
|---|---|
| 1〜3 の間 | **何も変わらない。** 新しい場所に半端なコピーが残るだけ |
| 4 の直後 | 両方にデータがある。**新しい方が使われる**ので実害は無い |
| 5 が失敗 | 同上。**消せなかった場所を画面に出す** |

**先に消してから書く順にしない。** そうすると 4 の直前で落ちたときに、
**データは移ったのに指定は古いまま**になり、利用者からはデータが消えたように見える。

ADR-0023 決定 6（ホットキーは登録してから保存）と同じ形。

### 4. 移すかどうかは利用者に尋ねる

```
データの保存先を変更します。

  いま : C:\Users\…\AppData\Local\NutLens （3 件の履歴、142 MB）
  変更後: D:\NutLensData

いまのデータを新しい場所へ移しますか？
（移さない場合、新しい場所は空から始まります。元のデータは残ります）

［移して切り替える］　［移さずに切り替える］　［キャンセル］
```

**「移さずに切り替える」を残す。** 大きなモデルを含むと移動に時間がかかり、
手で移したい利用者もいる。**黙って移さない。**

### 5. Whisper のモデルも同じ場所に置く

利用者の選択。規則を 1 つにする。

モデルだけ別の場所に置きたい場合は、`whisper.modelPath` で個別に指定できる
（段階 3 から変わらない）。

### 6. アンインストールのときも、指定された保存先を見る

`Program.OnBeforeUninstall` は、いま `%LOCALAPPDATA%\NutLens` を直接見ている。
**指定を読んでから消す**ように直す。

**直さないと、保存先を変えた利用者の `work\` が消えずに残る**（D-01 違反）。

なお `data-dir.txt` はインストール先にあるので、アンインストールで一緒に消える。
**保存先のデータ自体は残る**（ADR-0027 決定 3 のとおり、履歴は黙って消さない）。

## 影響

- `DataRoot`（Core の純ロジック）が増える。解決・読み書き・移動
- `AppDataPaths` は変えない。**根を受け取る形は最初からそうなっていた**
- 合成ルートが `DataRoot.Resolve(…)` を呼んで根を決める
- `Program.OnBeforeUninstall` が指定を読むようになる
- 設定画面の「高度な設定（上級者向け）」に、現在の保存先と変更の口が増える
- **D-05 の状態が 🔨 から ✅ になる**（保存先が設定で変えられるようになるため）

## 宿題

- **一度も移していない。** 大きなモデルを含む移動の時間が未測定
- ネットワークドライブや、書き込めない場所を指定されたときの挙動（検査はするが未検証）
- 移動の最中にアプリをもう 1 つ起動された場合（多重起動の防止はまだ無い）
- 保存先を変えた状態での更新・アンインストールが未検証

## 却下した案

| 案 | 却下の理由 |
|---|---|
| インストール先の `data\` に固定する（完全ポータブル） | **アンインストールで履歴も消える。** D-01 は「履歴を残すかどうかは利用者が選べる」と言っている。利用者もこちらを選ばなかった |
| 保存先を `settings.json` に書く | **`settings.json` 自身が保存先の中にある。** どこを読めばよいかが決まらない（決定 2） |
| 「場所の指定」を exe の隣（`current\`）に置く | **更新のたびに `current\` は作り直される。** 指定が消えて初期値に戻り、「更新したら履歴が消えた」ように見える（決定 2） |
| 「場所の指定」をレジストリに持つ | C: を使いたくないという要望に対して、**C: のレジストリに書くのは筋が違う。** ポータブル版でも持ち運べない |
| 環境変数で指定させる | 設定画面から変えられない。D-05 の「設定で変えられる」に届かない |
| 解決を 3 段（設定 → インストール先 → LOCALAPPDATA）にする | **いまどこを見ているかが分からなくなる。** 2 段に抑え、現在地を画面に出す（決定 1） |
| 変更したら黙って移す | 1.5 GB の移動が黙って始まる。**手で移したい利用者の選択肢も消える**（決定 4） |
| 変更したら移さない（常に空から） | 利用者からは「履歴が消えた」ように見える |
| 元を消してから指定を書く | 書く直前で落ちると、**データは移ったのに指定は古いまま**になる（決定 3） |
| モデルだけ別の場所を既定にする | 規則が 2 つになる。個別指定の道（`whisper.modelPath`）は既にある（決定 5） |
