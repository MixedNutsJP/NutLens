# ADR-0014. analyzer/ をセッションフォルダへ複製し、プロンプトのテンプレートもそこに置く

- 状態: **実測・実機で確認**（2026-11-13。配置して `claude -p` が読むことを確認）
- 日付: 2026-11-13

## 背景

F-23 は「セッションフォルダに `analyzer/` の CLAUDE.md と `.claude/` を**コピーし（またはリンクし）**、
そこを作業ディレクトリにして `claude -p` を起動する」。
F-21 は「テンプレートは外部ファイルにして編集できるようにする」。

決めるべきことが 3 つある。

1. コピーかリンクか
2. テンプレートをどこに置くか（アプリのインストール先か、利用者が編集できる場所か）
3. 利用者が壊したときにどう戻すか

制約として、ADR-0006 決定 6 で**作業ディレクトリの外を Read させない**ことにしている
（`--add-dir` を渡さない）。リンクで外へ出す経路を作ると、この方針と噛み合わない。

## 決定

### 1. コピーする。リンクは使わない

ハードリンク・ジャンクションは、作成に権限が要る場合があり、
**アンインストールや一時データの削除で「リンク先まで消える」事故**が起こりうる。
`analyzer/` は合計で数十 KB しかないので、毎回コピーしても費用はない。

### 2. 置き場を 2 段にする

```
<インストール先>\analyzer\                     既定（アプリに同梱。利用者は触らない）
%LOCALAPPDATA%\NutLens\analyzer\               利用者の編集用（あればこちらを優先）
    CLAUDE.md
    prompt-template.md
    schema\result.schema.json
    .claude\skills\identify-movie\SKILL.md
```

`%LOCALAPPDATA%` 側が存在すればそちらを、無ければ同梱版を使う。

**同梱版を直接編集させない。** アプリを更新すると（D-02 の自動更新）上書きされ、
利用者の編集が黙って消える。消えたことに気づけるのは、結果がおかしくなった後になる。

設定画面に「編集用にコピーする」「既定に戻す」を置く（段階 4）。

### 3. 毎回コピーし、既にあっても上書きする

セッションフォルダは毎回新規なので、実際には常に新規コピーになる。
再調査（F-27）では同じフォルダを使い回すが、そのときも上書きする。
**途中で原本が変わったら次の解析から反映される**という、読み手が予想しやすい挙動にする。

### 4. プロンプトのテンプレートも `analyzer/` に置く

F-21 の「外部ファイル」をここで満たす。CLAUDE.md・SKILL.md・スキーマと
**同じ場所に置くことで、4 つの整合を一度に見られる**ようにする。
（テンプレートが参照するフレームの並べ方と、SKILL.md の手順がずれると結果が崩れる）

テンプレートの差し込みは `{{名前}}` の単純な置換にする。
条件分岐やループは入れない。入れると「テンプレート言語」を保守することになる。

| プレースホルダ | 中身 |
|---|---|
| `{{frames}}` | フレームの相対パスと撮影時刻の一覧 |
| `{{transcript}}` | 文字起こし（段階 3。無ければ「（なし）」） |
| `{{ocr}}` | OCR の結果（段階 3。無ければ「（なし）」） |
| `{{web_detection}}` | Web Detection の参考情報（段階 3 の後。無ければ「（なし）」） |
| `{{notes}}` | 利用者のメモ（URL・投稿者名・キャプション・自由メモ） |
| `{{schema}}` | 出力スキーマの相対パス |

**未知のプレースホルダは置換せずそのまま残す。** 消すと、利用者がテンプレートを
編集して打ち間違えたときに「黙って消えた」ことに気づけない。

### 5. 生成したプロンプトは `prompt.md` として保存する

F-22（送る前に確認・編集できる）の編集結果も `prompt.md` に反映する。
`claude -p` には**編集後の内容**を渡す。`prompt.md` は一時データ（5.5）。

## 実装で分かったこと（2026-11-13）

### 1. 配置は意図どおりに動いた

セッションフォルダの中身（通し確認の実測）:

```
CLAUDE.md
prompt-template.md
prompt.md                                   ← 生成したプロンプト
frames\frame_001_t0000.0s.jpg
frames\frame_002_t0002.4s.jpg
schema\result.schema.json
.claude\skills\identify-movie\SKILL.md
```

### 2. `CLAUDE.md` と `SKILL.md` は確実に効いていた（宿題の回答）

出力の中身がそれを示している。

- `candidates` が**空のまま返った**。入力が映画ではないので正しく、
  `CLAUDE.md` の「守ること 3：無理に 1 つ挙げない」が効いている
- `observed_features` が `SKILL.md` 手順 1 の表（場面・舞台・時代・言語・テロップ・小道具・表現）
  に沿って並んでいた
- 「真っ黒ではない」と明記された。`SKILL.md` 手順 1 の**HDCP で取れていない場合の指示**が読まれている
- `search_queries_used` が空。手がかりが無いので検索しなかった旨が
  `unverified_points` に書かれていた

**プロンプトから `/identify-movie` と呼ぶ必要はなかった。** 作業ディレクトリに置くだけで読まれた。

### 3. ビルドで `.claude/` を含める指定が要る

`<Content Include="..\..\analyzer\**\*.*" LinkBase="analyzer" />` と明示的に書く。
既定のグロブでは隠しフォルダ（`.claude`）が落ちる。
**落ちても配置自体は成功し、解析の質だけが下がる**ので、気づきにくい形の不具合になる。

## 影響

- 配布物に `analyzer/` を含める必要がある（段階 5 のパッケージング）
- セッションフォルダに `CLAUDE.md` / `.claude/` / `schema/` が増える。
  これらは一時データとして他と一緒に消える
- 利用者が `%LOCALAPPDATA%\NutLens\analyzer\` を壊すと解析が崩れる。
  「既定に戻す」を用意する（段階 4）

## 宿題

- 設定画面の「編集用にコピーする」「既定に戻す」（段階 4）

### 片付いた宿題

- ~~セッションフォルダの `CLAUDE.md` が読まれるか~~ → 読まれた（実装で分かったこと 2）
- ~~`.claude/skills` が自動で見つかるか~~ → 見つかった。`/identify-movie` と呼ぶ必要はない

## 却下した案

| 案 | 却下の理由 |
|---|---|
| シンボリックリンク / ジャンクションを張る | 作成に権限が要る場合がある。さらに**一時データの削除で、リンク先の原本まで消える**事故がありうる。消えるのは原本で、気づくのは次の解析のとき |
| `--add-dir` で `analyzer/` の原本を参照させる（コピーしない） | Read の到達範囲がインストール先まで広がる。ADR-0006 決定 6（作業ディレクトリに閉じる）と噛み合わない |
| テンプレートをアプリに埋め込み（埋め込みリソース）にする | F-21 の「外部ファイルにして編集できるようにする」を満たさない |
| 同梱の `analyzer/` を利用者に直接編集させる | 自動更新（D-02）で**黙って上書きされる**。消えたことに気づくのは結果がおかしくなった後 |
| テンプレートに条件分岐やループを入れる（Scriban / Handlebars 等） | 依存が 1 つ増え、テンプレート言語の保守が始まる。差し込むのは 6 項目で、単純置換で足りる |
| 未知のプレースホルダを空文字に置換する | 打ち間違いが**黙って消える**。残しておけば、生成されたプロンプトを見た時点で気づける（F-22 で必ず目を通す） |
| プロンプトをファイルに書かず、標準入力で渡す | F-22（送る前に確認・編集）と 5.5（`prompt.md` を一時データとして置く）が `prompt.md` の存在を前提にしている |
