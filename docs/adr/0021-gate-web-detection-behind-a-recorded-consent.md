# ADR-0021. Web Detection の有効化を同意ダイアログだけの入口にし、同意した版を記録する

- 状態: **採用**（2026-11-14 承認）
- 日付: 2026-11-14

## 背景

5.6 はこう書いている。

> **初期値はオフ**。設定画面の「高度な設定（上級者向け）」の中に置き、そのラベルを画面に表示する。
> 有効にするときは確認ダイアログを出し、次の 3 点を説明して同意を得る：
> (1) 選んだフレームが Google に送られること、
> (2) 利用者自身の Google Cloud の API キーと課金が必要で、利用料がかかる場合があること、
> (3) Google Cloud の規約に従って使うこと。

ここで、いまの作りと噛み合わない点が 2 つある。

**1 つめ。設定は利用者が手で書き換えられる。**

```csharp
// NutLensSettings.Normalize() の既存コメント
// 設定ファイルは利用者が手で書き換えられる。
// "capture": null のように書かれると、プロパティ初期化子を素通りして null が入る。
```

`settings.json` に `"webDetection": { "enabled": true }` と書くだけで送信が始まるなら、
**同意ダイアログは飾りになる。**「オフが既定」も、ファイルを 1 行書き換えれば覆る。

**2 つめ。設定画面は段階 4 で、まだ無い。**

同意ダイアログを設定画面の中に作るなら、段階 3' の成果物は
「設定ファイルを手書きしないと動かない機能」になる。
**その手書きこそが、1 つめで防ごうとしている迂回そのもの。**

## 決定

### 1. 送信の条件を 3 つの AND にする

次がすべて成り立つときだけ送る。1 つでも欠ければ、Web Detection は**使わない**（解析は続く）。

| 条件 | どこで決まるか |
|---|---|
| `WebDetection.Enabled == true` | `settings.json` |
| `WebDetection.ConsentVersion == WebDetectionSettings.CurrentConsentVersion` | `settings.json`。**書くのは同意ダイアログだけ** |
| 資格情報マネージャーに鍵がある | Windows 資格情報マネージャー（ADR-0020） |

`settings.json` を手で書いて `enabled` を立てても、`consentVersion` は 0 のままなので**有効にならない**。
API キーも `settings.json` には無い（ADR-0020 決定 4）ので、手書きでは供給できない。

**迂回を「禁止」ではなく「成立しない」形にする。** 検査を足して弾くのではなく、
手書きでは揃えられない条件を混ぜる。

### 2. `ConsentVersion` を書くのは同意ダイアログだけ

「同意する」を押したときに、`Enabled = true` と `ConsentVersion = CurrentConsentVersion` を
**同じ保存で一緒に書く。** 片方だけ書く経路をコードに作らない。

無効化はいつでもできる（`Enabled = false` にするだけ）。`ConsentVersion` は消さない。
一度読んで同意した事実は、オフに戻しても変わらないため。

### 3. ダイアログの本文は 5.6 の 3 点をそのまま出す

```
Web Detection を有効にします。

・選んだフレーム（最大 3 枚）が Google に送られます。
・利用者ご自身の Google Cloud の API キーと課金設定が必要です。利用料がかかる場合があります。
・Google Cloud の規約に従ってご利用ください。

送るのはフレーム全体です。顔の検出や人物の特定には使いません。
```

文字列は `NutLens.App/Resources/Strings.resx` に置く（D-09。XAML に日本語を直接書かない）。

### 4. 同意文を変えたら `CurrentConsentVersion` を上げる

上げた版では、**既に同意していた利用者も自動的にオフへ戻り、もう一度同意を求められる。**

これは不便だが意図したもの。送る内容や送り先の説明が変わったのに、
古い同意のまま送り続けるのは「同意を得た」と言えない。

初版は `CurrentConsentVersion = 1`。

### 5. 段階 4 を待たず、有効化の入口だけ段階 3' で作る

メイン画面の「高度な設定（上級者向け）」という**ラベルつきの折りたたみ**に、次の 3 つを置く。

- Web Detection を使う（チェックボックス。オンにしようとすると同意ダイアログが出る）
- API キーを設定する…
- API キーを削除する

段階 4 で設定画面を作るときに、この 3 つをそちらへ移す。
**「高度な設定（上級者向け）」というラベルを画面に出すこと自体が 5.6 の要求**なので、
折りたたみの見出しをその文字列にする。

### 6. 設定ファイルの版（`NutLensSettings.CurrentVersion`）は上げない

`WebDetection` は**新しく足す項目**で、既存の項目の意味は変わらない。
ADR-0015 のときのような移行（しきい値の意味が変わった）は要らない。

ただし `Normalize()` には `this.WebDetection ?? new WebDetectionSettings()` の受けを足す。
`"webDetection": null` と書かれた設定ファイルで落ちないようにするため
（ソース生成の逆直列化はプロパティ初期化子を走らせない。既に同じ事故を起こしている）。

## 影響

- `WebDetectionSettings` に `ConsentVersion`（`int`、既定 0）が増える
- メイン画面に折りたたみが 1 つ増える。既定は閉じた状態
- 同意ダイアログは `IUserInteraction` 経由で出す。ViewModel が `MessageBox` を直接呼ばない（ADR-0002 決定 4）
- 「オンにしようとしたが同意しなかった」場合、チェックボックスは**元に戻す**。
  押した結果が画面に残らないと、有効になったのかどうかが分からない

## 実装で分かったこと（2026-11-14）

### 1. 3 条件の判定はテストで固定した

`WebDetectionGateTests` で 6 件。特に次の 2 つが要（どちらも成功）。

| 確かめたこと | 結果 |
|---|---|
| 既定の設定では送らない | 送らない |
| **`enabled` だけ true にしても送らない**（手書きの迂回） | 送らない（`ConsentOutdated`） |

`WebDetectionServiceTests` でも「既定では `IWebDetectionClient` を一度も呼ばない」
ことを確かめている。**判定が緩んだらテストが落ちる。**

### 2. 同意しなかったときにチェックを戻すのは、同じプロパティの通知で足りる

`CheckBox` は既に見た目が変わっているので、値を変えずに
`RaisePropertyChanged(nameof(Enabled))` を呼んで読み直させる。

### 3. 画面に出さない理由が 1 つある

`Disabled`（設定でオフ）だけは警告に出さない。
既定の状態なので、出すと**使っていない利用者に撮影のたびに出る。**

## 宿題

- **ダイアログと折りたたみを目視していない**（段階 2・3 の画面も未目視のまま）
- 鍵を入れずに有効化したときの案内の文面（「鍵が無いので使われません」をどこに出すか）
- 段階 4 で設定画面へ移すとき、折りたたみをメイン画面から**消す**か残すか

## 却下した案

| 案 | 却下の理由 |
|---|---|
| `Enabled` だけを見る | `settings.json` を 1 行書き換えれば同意なしで送信が始まる。**同意ダイアログが飾りになる**（決定 1） |
| `Enabled` を見つつ、設定ファイルが手書きかどうかを検出して弾く | 検出のしようがない（ファイルの更新時刻も署名も当てにならない）。**検査を足すより、手書きでは揃えられない条件を混ぜるほうが確実**（決定 1） |
| 鍵が入っていることをもって同意とみなす | 鍵を入れた＝送ってよい、ではない。鍵の設定と送信の許可は別の判断。**鍵だけ先に入れて後で考える**という使い方を塞いでしまう |
| 起動のたびに同意を聞く | 毎回押させると読まれなくなる。「はい」を押す動作だけが習慣になり、同意の意味が失われる |
| 同意に版を持たせない | 同意文を変えても古い同意が通り続ける。**送る内容の説明が変わったのに、変わる前の同意で送る**ことになる（決定 4） |
| 設定画面（段階 4）ができるまで有効化の口を作らない | 段階 3' の成果が「設定ファイルを手書きしないと動かない機能」になる。**その手書きが、決定 1 で塞ごうとしている迂回そのもの**（決定 5） |
| 同意したら `ConsentVersion` を資格情報マネージャー側に書く（手書き不能にする） | 鍵と同意が同じ置き場になり、「鍵を消したら同意も消える」など挙動が絡まる。`settings.json` 側で足りる |
